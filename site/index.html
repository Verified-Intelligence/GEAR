The idea

From verifying networks to certifying optima

A neural network verifier bounds the outputs of a computation graph over a box of inputs. Linear bound propagation does this with a linear lower and upper bound for every output, and it runs on GPUs for thousands of boxes at once. A nonlinear program over a box is a computation graph too: its objective and constraints are the outputs.

Verification alone is not a solver. It bounds each output separately, so the objective bound of a box comes from points that may violate the constraints, and it never produces a feasible point to prune against. The key observation is that verification keeps only the minimum of each linear bound, while the bounds themselves relax every constraint. Their Lagrangian combination is an LP dual that GEAR evaluates in closed form for every box, so the GPU never solves an LP.

The price is a looser bound per box than an LP with all McCormick planes. GEAR pays it back by bounding thousands of boxes per GPU step, which wins on highly nonlinear problems of low and moderate dimension and loses on large structured models (analysis).

dB(λ) = minx∈B [ f0(x) + λT(Ax + c) ]

The Lagrangian bound. f0 is the linear lower bound of the objective and Ax + c ≤ 0 stacks the linear lower bounds of the constraints on the box B, with a(λ) = a0 + ATλ. Every λ ≥ 0 gives a valid lower bound on the box in closed form; GEAR raises it by a fixed number of batched steps on λ per box. The multipliers λ act on the linear bounds and are distinct from the ALM multipliers of the primal search.

BOUND

Lower bound

The Lagrangian bound uses the constraints to prune boxes whose low objective comes from infeasible points.

CLIP

Clipping

The constraint bounds cut the box and the intermediate domains before the next pass.

PROVE

Infeasibility

A box is removed when a nonnegative combination of the relaxations is violated everywhere on it.

SEARCH

Primal search

A projected ALM starts from the minimizers of the Lagrangian bound; every point is re-verified on the original model.

BRANCH

λ-SB

λ-weighted smart branching scores coordinates from the same coefficients and multipliers.

Compile

once per problem

  • Computation graph with the objective and constraints f0, …, fm as its outputs
  • Linear constraints kept exact, outside the graph

Root node

one batched GPU pass

  • Linear bounds of the objective and all constraints
  • Lagrangian bound with clipping gives the lower bound D
  • Projected ALM from batched starts gives the incumbent P, re-verified at 10−6

GPU branch-and-bound

one batch of thousands of boxes per step

select→bound→prune→search→branch↻
  • Select the boxes with the lowest D; bound them with linear bounds, clipping and the Lagrangian bound
  • Prune a box when D ≥ P or when it is certified empty
  • Branch on the λ-SB coordinate at its midpoint

Certificate

what a solved instance returns

  • P: a point verified on the original model
  • D: a valid lower bound, in fp64
  • Solved when the relative gap is at most 10−4

The full solver, including presolve, the root certificates and the lifted linear relaxation, is described component by component in Appendix B of the paper.

Results

421 of 505 instances certified in 180 seconds

505 bounded continuous nonlinear programs, 265 from gams_world and 240 from MINLPLib, against six global and six local solvers through AMPL. Every solver runs on the same workstation (8-core AMD Ryzen 9700X with 16 threads, 256 GB, one RTX 5090) for 180 s per instance, in one configuration tuned on a 40-instance subset. Local solvers prove no bound; they are credited only when their point matches a bound certified by a global solver.

Analysis

Where the GPU helps, and where it does not

The benchmark mixes small transcendental puzzles with large structured models. Broken down by size, constraint count and the kind of nonlinearity, the comparison shows one regime that GPU batching wins clearly and one it does not.

Share of each problem class certified

Global union: the instances certified by at least one of the six global solvers. The two columns on the right count the instances only GEAR, or only the union, certifies. Appendix E of the paper.

322 / 330

Batching wins on composite nonlinearities in low dimension.

GEAR certifies 322 of the 330 instances with at most 20 constraints (SCIP 278, Gurobi 298) and 131 of 147 with exponential, logarithmic, square-root or trigonometric terms (SCIP 100, Gurobi 110). Relaxations of such compositions are loose, so a CPU branch-and-bound processes many weak nodes one after another; GEAR bounds thousands of boxes per GPU step and splits them aggressively.

20 / 22

Cutting planes still win on large structured models.

Above 20 constraints GEAR certifies 99 of 175 against Gurobi’s 103, and 20 of the 22 instances only the global union certifies are pooling, wastewater, water-network and circle-packing models. Their certificates rely on LP-based branch-and-bound with RLT and other cutting planes, and splitting boxes in thousands of dimensions is expensive; GEAR certifies no instance above 1,000 variables.

Reproduce

Check every number

The repository holds the 505 models, the baseline harness with every configuration it tried, the log of every run behind the tables, and the scored per-instance results. The GEAR source will be released in the same repository; until then, its configuration and the exact command of every run are published with its logs.

  1. The scoring rule

    A run is solved when its returned point satisfies every constraint and bound of the original model, with equalities kept exact, to absolute tolerance 10−6, and its primal value P and certified lower bound D satisfy

    (P − D) / max(1, |P|, |D|) ≤ 10−4.

    Baseline points are re-evaluated in AMPL; GEAR replays its point on the original model before returning it. Local solvers have no D: they are credited when their feasible P matches the tightest bound a global solver certified. A certificate contradicted by a better feasible point from any run is withdrawn, and an infeasibility verdict counts once two global solvers confirm it.

  2. Get the logs and verify them

    One archive per solver, one log per instance, local paths replaced; checksums cover every archive, the GEAR configuration, its per-instance results and the manifest.

    git clone https://github.com/Verified-Intelligence/GEAR.git
cd GEAR
(cd logs && sha256sum -c SHA256SUMS)
tar -xJf logs/gear.tar.xz       # gear/<family>/<instance>.log

  3. Recount the table from the scored results

    One row per solver and instance, with the certificate, P, D, the maximum violation and the time. The count reproduces Table 1.

    # global solvers: column 6 (criterion b); local solvers: column 10 (match with a certified bound)
awk -F'\t' 'NR>1 && (($2=="global") ? $6 : $10)==1 {n[$1]++} END {for (s in n) print s, n[s]}' \
    baselines/results/per_instance_long.tsv
# GEAR: one row per instance, column 4 = certified
awk -F'\t' 'NR>1 && $4==1 {n++} END {print "gear", n}' logs/gear_results.tsv

  4. Rerun the baselines

    The harness runs each solver through its AMPL driver with the chosen configuration; the full pipeline tunes on the 40-instance subset and then runs all 505 instances. baselines/commands.md lists the exact option strings and thread layout of every solver.

    pip install amplpy
python -m amplpy.modules install base coin baron knitro lgo lindoglobal minos scip snopt gurobi xpress conopt
python -m amplpy.modules activate <your-license-uuid>
cd baselines
python harness/bl.py drive --config configs/chosen/gurobi_cfg.json --run final_gurobi --time-limit 180
bash harness/run_campaign.sh     # all solvers: tuning, then the final runs

  5. The GEAR runs

    One instance at a time on one RTX 5090 with 16 CPU threads, the same configuration for all 505 instances. Every GEAR log starts with the command that produced it, for example:

    python nlp_example.py --problem_name hs101 --benchmark gams_world --benchmark_root benchmarks \
    --device cuda --override_timeout 180.0 --config configs/int3p_crownmerge.yaml

    The Configurations: block printed at the top of a GEAR log lists argument defaults, not the settings in effect; those are in int3p_crownmerge.yaml.

  6. Inspect any instance

    The gap atlas shows, for any subset of GEAR and the 12 AMPL solvers, which of them certify each instance, how each certified bound closes over time, the formulation, the command and the full logs.

    baselines/benchmark/the 505 AMPL models and manifest.tsv (family, instance, sense, size, sha256)
    baselines/configs/every configuration tried in tuning, the chosen one per solver, the 40-instance subset
    baselines/results/scored per-instance tables, the final table and the tuning log
    logs/logs of the 13 final runs, gear_results.tsv, the GEAR configuration, manifest and checksums
